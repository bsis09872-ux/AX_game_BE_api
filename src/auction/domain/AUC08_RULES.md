# AUC-08 연속 낙찰 제한 — 제재 후 초기화(B)

확정 규칙 문서다. 현재 policies.py는 이전 방식이며 아래 정책은 아직 구현되지 않았다.

## 집계와 차단

- Trade.buyer_id별 Trade.completed_at을 UTC로 집계한다.
- 평상시 최근 30분 내 낙찰이 3건이 되는 세 번째 체결 시각부터 10분간 새 입찰을 막는다.
- 30분 경계는 포함한다. 조회와 기존 입찰의 정산은 허용한다.
- 차단 중 추가 낙찰은 Trade에 남기되 기존 차단 종료 시각을 연장하지 않는다.
- 차단 종료 정각부터 입찰을 허용하고 이전 집계 주기는 초기화한다.
- 과거 Trade는 삭제·수정하지 않는다. 만료된 blocked_until도 다음 주기 기준으로 보존한다.
- 차단이 만료된 뒤 유효 기록은 `max(now - 30분, 보존된 blocked_until) <= completed_at <= now` 범위다.
- 이전 차단이 없다면 `now - 30분 <= completed_at <= now`로 집계한다.
- 종료 시각 이전 기록은 제외하고 종료 정각의 새 낙찰은 새 주기에 포함한다.
- 제한 종료 후 새 거래가 없다면 0/3이다. 새 거래가 있다면 새 주기의 유효 횟수를 반환한다.

## 데이터 책임

- User는 auction_purchase_count와 auction_blocked_until을 저장한다.
- Auction domain은 횟수·차단 발동·초기화·남은 시간 규칙을 계산한다.
- Auction application은 Trade 조회, User 상태 조회·갱신, 트랜잭션을 조율한다.
- 저장된 횟수만으로 30분 조건을 판단하지 않는다. Trade 기록으로 유효 횟수를 다시 계산한다.
- Domain에는 User ORM·SQLAlchemy를 import하지 않는다.

## 시간과 응답

- 모든 입력 시각은 timezone-aware UTC다. domain에서 현재 시각을 직접 읽지 않는다.
- 차단 여부는 now < blocked_until, 남은 시간은 max(blocked_until - now, 0)이다.
- API는 유효 횟수·최대 3회·제한 여부·종료 시각·남은 초를 제공한다.
- API 시각은 UTC ISO 8601, 화면 표시는 KST다. UTC 01:37은 KST 10:37이다.
